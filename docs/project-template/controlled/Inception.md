# Inception

## Problem and outcome

State the user problem, the observable outcome, and why the project should exist. Do not describe a
solution before the problem and success boundary are agreed.

## Stakeholders and system boundary

Name accountable stakeholders, external actors, trusted systems, untrusted inputs, and information
that must not cross the boundary.

## Assumptions and constraints

List only assumptions that affect design or verification. Give each a validation owner or an explicit
expiry condition. Record regulatory, cost, time, technology, and deployment constraints separately.

## Scope

Define the smallest demonstrable vertical slice and its later concentric increments. State non-goals
that prevent adjacent concerns from silently expanding the delivery.

## Risks and exit criteria

Describe the highest-impact failure modes, mitigations, and the evidence required to accept or stop the
project. Link resulting requirements and decisions by stable identity rather than copying their text.
